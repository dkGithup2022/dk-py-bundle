# Entity References

`be-add-entity-specs` 스킬이 참고하는 Entity (SQLAlchemy 2.0 매핑 클래스) 작성 레퍼런스.

> **이 문서의 성격 (공통)**
>
> - 기존 서비스 패턴에서 도출된 **참고용** 자료다. 절대 규칙이 아니라 결과물의 경향을 맞추기 위한 가이드.
> - 요구사항이 이 패턴들로 해결되지 않으면, 주변 컨텍스트(폴더/파일/연관 패키지)를 **한 번 더 탐색·검토** 후 필요한 변형을 적용한다.
> - 여러 레퍼런스로 해결 가능하면 **가장 간단한 방식**을 택한다.

---

## 공통 요소

### Entity 는 가변, 도메인은 불변

SQLAlchemy Entity 는 세션이 추적하는 **가변 객체**다. 도메인 모델(frozen dataclass)과 달리 필드를 제자리에서 바꾼다. `soft_delete()` 같은 전이 메서드도 새 인스턴스를 만들지 않고 `self` 를 바꾼다 — 새 인스턴스를 만들면 세션에 같은 PK 의 객체가 둘 생긴다.

### Auditing + soft-delete 4필드 직접 선언

dataclass 와 SQLAlchemy 매핑 클래스는 공통 부모를 가질 수 없으므로 abstract BaseEntity 상속 대신 각 Entity 가 직접 필드를 선언한다 (be-init §4.4 / C-3, C-4). `Base` 는 컬럼을 갖지 않는다.

모든 Entity 가 보유할 필드 4개:
```python
is_deleted: Mapped[bool] = mapped_column(Boolean, nullable=False, default=False, server_default=false())
deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), nullable=False, default=utcnow)
updated_at: Mapped[datetime] = mapped_column(
    DateTime(timezone=True), nullable=False, default=utcnow, onupdate=utcnow
)
```

`utcnow` 는 `{pkg}.model.audit.utcnow` (`persistence.base` 가 re-export). `created_at`/`updated_at` 두 필드가 `AuditFields` Protocol 구조를 만족한다.

**`onupdate` 의 한계**: `update()` 문으로 직접 갱신할 때는 `onupdate` 가 돌지 않는다. 감사 컬럼이 있는 테이블에 `update()` 문을 쓰면 `.values(..., updated_at=utcnow())` 를 직접 넣는다. Stats 테이블은 감사 컬럼이 없어 해당 없음.

**예외**: Stats 분리 Entity (Pattern Bar) 와 aggregate 자식 컬렉션 Entity (Pattern Baz 의 자식) 는 audit/soft-delete 미적용 — 이유는 해당 섹션 참조.

### `__tablename__`, `id`, 타입 규칙

- `__tablename__ = "{snake_case_복수형}"` 필수 (`foos`, `community_posts`)
- `id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)` — 테이블 내부 PK. 도메인 모델의 `{domain}_id` 와 1:1 매핑되지만 Entity 에서는 `id` 명명. Postgres `GENERATED BY DEFAULT AS IDENTITY` 로 생성됨
  - **`Mapped[int]` 이어야 한다.** `Mapped[int | None]` 로 쓰면 SQLAlchemy 가 PK 를 nullable 로 보고 `alembic check` 가 `modify_nullable` 을 계속 보고한다 (실행으로 확인). 신규 Entity 는 `id` 를 안 넘기면 되므로 `None` 타입이 필요 없다.
  - **`Identity()` 명시.** `autoincrement=True` 만 쓰면 Postgres 에서 `SERIAL`(`nextval`) 로 생성된다. `Identity()` 가 `GENERATED BY DEFAULT AS IDENTITY`.
- 문자열: `String(255)` 또는 `Text`
- 정수: `BigInteger` (id/FK), `Integer` (카운터 등)
- enum: `Enum({StrEnum}, native_enum=False, length=255)` — Postgres 네이티브 enum 금지 (값 추가 시 migration 이 단순)
- 시각: `DateTime(timezone=True)` → `timestamptz`
- 모든 Entity 는 `{pkg}.persistence.base.Base` 상속
- Entity 모듈은 `persistence/entities.py` 에 한 줄 등록 (C-6) — Alembic 과 테스트가 metadata 를 완성하는 유일한 경로

### to_domain / from_domain / soft_delete 메서드 시그니처

모든 Entity 가 다음 3개를 제공 (Pattern Bar 와 자식 컬렉션은 `soft_delete` 제외):

```python
def to_domain(self) -> {Domain}: ...                       # Entity → Domain
@classmethod
def from_domain(cls, domain: {Domain}) -> Self: ...        # Domain → Entity (신규: is_deleted=False, deleted_at=None)
def soft_delete(self) -> None: ...                         # 제자리: is_deleted=True, deleted_at=utcnow(), updated_at=utcnow()
```

- `from_domain()` 의 `is_deleted`/`deleted_at` 초기값은 항상 `False` / `None`
- `soft_delete()` 는 `updated_at` 도 함께 갱신 (`onupdate` 가 돌기는 하지만 명시)
- `created_at` 은 `soft_delete` 에서 **유지**
- `from` 은 예약어라 `from_domain`

### relationship 규칙

- **같은 aggregate 의 자식 컬렉션에만** `relationship(...)` 허용 (Java `@MappedCollection` 범위)
- 항상 `lazy="selectin"` (부모 로드 시 IN 절 한 번으로 자식 로드, 속성 접근 시 몰래 쿼리 없음) + `cascade="all, delete-orphan"`
- **다른 aggregate 로의 relationship 금지** (`foos.user_id → users` 같은 것). 작성자명 등은 어댑터가 `select().join()` 으로 가져온다
- 자식 Entity 의 FK 컬럼은 `ForeignKey("{parent_table}.id")` 로 선언 — ORM 조인 조건용. **DB FK 제약은 생성되지 않는다** (`env.py` 필터, C-5)

## Pattern Foo — 단순 Entity

**언제 쓰나**: 다른 테이블과의 컬렉션 관계 없는 flat 테이블 (평점, 북마크, 반응, 유저, 알림 등).

```python
from datetime import datetime
from typing import Self

from sqlalchemy import BigInteger, Boolean, DateTime, Enum, Identity, Integer, false
from sqlalchemy.orm import Mapped, mapped_column

from {pkg}.model.foo.foo import Foo
from {pkg}.model.foo.foo_source import FooSource
from {pkg}.persistence.base import Base, utcnow


class FooEntity(Base):
    __tablename__ = "foos"

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    user_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    target_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    source: Mapped[FooSource] = mapped_column(
        Enum(FooSource, native_enum=False, length=255), nullable=False
    )
    score: Mapped[int] = mapped_column(Integer, nullable=False)

    is_deleted: Mapped[bool] = mapped_column(
        Boolean, nullable=False, default=False, server_default=false()
    )
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, default=utcnow
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, default=utcnow, onupdate=utcnow
    )

    def to_domain(self) -> Foo:
        return Foo(self.id, self.user_id, self.target_id, self.source, self.score,
                   self.created_at, self.updated_at)

    @classmethod
    def from_domain(cls, domain: Foo) -> Self:
        return cls(
            id=domain.foo_id,
            user_id=domain.user_id,
            target_id=domain.target_id,
            source=domain.source,
            score=domain.score,
            is_deleted=False,
            deleted_at=None,
            created_at=domain.created_at,
            updated_at=domain.updated_at,
        )

    def soft_delete(self) -> None:
        now = utcnow()
        self.is_deleted = True
        self.deleted_at = now
        self.updated_at = now
```

**특징**:
- 구성 파일: `foo_entity.py` 1개
- relationship 없음
- Pattern Bar(Stats) 가 아닌 이상 `soft_delete()` 제공
- `from_domain` 은 kwargs 로 (필드 순서 실수 예방). `id=domain.foo_id` 가 `None` 이어도 된다 — SQLAlchemy 생성자는 런타임 검사 없음

## Pattern Bar — Stats 분리 Entity (audit 미적용)

**언제 쓰나**: 본 도메인과 분리된 통계 테이블. 쓰기 경쟁 격리·조회 최적화 목적.

```python
class FooStatsEntity(Base):
    __tablename__ = "foo_stats"

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    foo_id: Mapped[int] = mapped_column(BigInteger, nullable=False, unique=True)
    view_count: Mapped[int] = mapped_column(BigInteger, nullable=False, default=0, server_default="0")
    rating_sum: Mapped[int] = mapped_column(BigInteger, nullable=False, default=0, server_default="0")
    rating_count: Mapped[int] = mapped_column(Integer, nullable=False, default=0, server_default="0")
    comment_count: Mapped[int] = mapped_column(Integer, nullable=False, default=0, server_default="0")

    def to_domain(self) -> FooStats:
        return FooStats(self.foo_id, self.view_count, self.rating_sum,
                        self.rating_count, self.comment_count)

    @classmethod
    def from_domain(cls, domain: FooStats) -> Self:
        return cls(
            id=None,
            foo_id=domain.foo_id,
            view_count=domain.view_count,
            rating_sum=domain.rating_sum,
            rating_count=domain.rating_count,
            comment_count=domain.comment_count,
        )
```

**특징**:
- audit/soft-delete **4필드 없음**
- `soft_delete()` 없음 — 통계는 원 도메인과 생애주기 동일, soft-delete 개념 불필요
- `id` (PK) + `{domain}_id` (unique) 2개 키 보유. `from_domain()` 에서 `id=None` 으로 insert
- 카운터는 `server_default="0"` 도 함께 (migration DDL 에 DEFAULT 0 이 들어가게)
- 구성 파일: `foo_stats_entity.py` 1개

## Pattern Baz — 자식 컬렉션 (relationship) 포함

**언제 쓰나**: 1:N 자식 레코드를 aggregate 내부 컬렉션으로 표현. enum 리스트 저장, 복합 VO 컬렉션 저장 등.

### 자식 Entity

각 자식 테이블마다 Entity 1개. **같은 도메인 디렉터리에 평면 배치** (`collection/` 서브디렉터리 생성 금지):

```python
class BazCategoryEntity(Base):
    __tablename__ = "baz_categories"

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    baz_id: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("bazs.id"), nullable=False   # ORM 조인용. DB FK 제약은 안 생김
    )
    category: Mapped[BazCategory] = mapped_column(
        Enum(BazCategory, native_enum=False, length=255), nullable=False
    )
```

복합 VO 컬렉션이면 여러 필드:
```python
class BazItemEntity(Base):
    __tablename__ = "baz_items"

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    baz_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("bazs.id"), nullable=False)
    linked_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    item_order: Mapped[int] = mapped_column(Integer, nullable=False)
```

자식 Entity 는 audit/soft-delete 4필드 **없음**, `to_domain`/`from_domain` 없음 (부모가 변환).

### Baz Entity

```python
class BazEntity(Base):
    __tablename__ = "bazs"

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    user_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    type: Mapped[BazType] = mapped_column(Enum(BazType, native_enum=False, length=255), nullable=False)
    title: Mapped[str] = mapped_column(String(255), nullable=False)
    body: Mapped[str] = mapped_column(Text, nullable=False)
    source: Mapped[BazSource] = mapped_column(
        Enum(BazSource, native_enum=False, length=255), nullable=False
    )

    categories: Mapped[list[BazCategoryEntity]] = relationship(
        lazy="selectin", cascade="all, delete-orphan"
    )
    tags: Mapped[list[BazTagEntity]] = relationship(lazy="selectin", cascade="all, delete-orphan")
    items: Mapped[list[BazItemEntity]] = relationship(
        lazy="selectin", cascade="all, delete-orphan", order_by="BazItemEntity.item_order"
    )

    is_deleted: Mapped[bool] = mapped_column(
        Boolean, nullable=False, default=False, server_default=false()
    )
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, default=utcnow
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, default=utcnow, onupdate=utcnow
    )

    def to_domain(self) -> Baz:
        return Baz(
            self.id, self.user_id, self.type, self.title, self.body,
            tuple(c.category for c in self.categories),
            tuple(t.tag for t in self.tags),
            self.source,
            tuple(BazItem(i.linked_id, None, i.item_order) for i in self.items),
            self.created_at, self.updated_at,
        )

    @classmethod
    def from_domain(cls, domain: Baz) -> Self:
        return cls(
            id=domain.baz_id,
            user_id=domain.user_id,
            type=domain.type,
            title=domain.title,
            body=domain.body,
            source=domain.source,
            categories=[BazCategoryEntity(category=c) for c in domain.categories],
            tags=[BazTagEntity(tag=t) for t in domain.tags],
            items=[BazItemEntity(linked_id=i.linked_id, item_order=i.order) for i in domain.items],
            is_deleted=False,
            deleted_at=None,
            created_at=domain.created_at,
            updated_at=domain.updated_at,
        )

    def soft_delete(self) -> None:
        now = utcnow()
        self.is_deleted = True
        self.deleted_at = now
        self.updated_at = now
```

**특징**:
- `relationship(lazy="selectin", cascade="all, delete-orphan")` — 부모 `save` 시 자식 insert, 부모 필드 교체 시 고아 자식 delete 를 SQLAlchemy 가 처리 (Java `@MappedCollection` 과 같은 자동 관리)
- 자식 FK 컬럼(`baz_id`) 은 `from_domain` 에서 채우지 않는다 — relationship 이 flush 시 채운다
- `to_domain()` 에서 `list → tuple` 변환 (도메인은 tuple)
- 수정 시 어댑터는 기존 Entity 를 조회해 필드와 컬렉션을 **제자리 교체** 한다 (`entity.categories = [...]`). `from_domain` 으로 새 Entity 를 만들어 `merge` 하지 않는다 — 자식 orphan 처리가 꼬인다
- `order_by` 는 순서가 의미 있는 자식(items)에만
- 구성 파일: `baz_entity.py`, `baz_category_entity.py`, `baz_tag_entity.py`, `baz_item_entity.py` 등 **자식 수만큼**

**금지**:
- `collection/` / `embedded/` 서브디렉터리 생성 금지 (평면 배치)
- `composite()` 사용 금지 (복합 VO 는 자식 테이블 + relationship 또는 컬럼 분해로 처리)
- `back_populates` / `backref` 금지 (자식은 부모를 모른다)
- `lazy="select"` (기본값) / `lazy="dynamic"` 금지 — 속성 접근 시 몰래 쿼리

## Pattern Qux — 상태 전이 메서드 (hide/show 등)

**언제 쓰나**: soft-delete 외에 추가 상태 전환(숨김/표시, 읽음/안읽음, 활성/비활성 등)이 있는 도메인.

```python
class QuxEntity(Base):
    __tablename__ = "quxs"

    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True)
    article_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    article_type: Mapped[QuxArticleType] = mapped_column(
        Enum(QuxArticleType, native_enum=False, length=255), nullable=False
    )
    user_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    text: Mapped[str] = mapped_column(Text, nullable=False)
    parent_id: Mapped[int | None] = mapped_column(BigInteger)
    qux_order: Mapped[int] = mapped_column(Integer, nullable=False)
    level: Mapped[int] = mapped_column(Integer, nullable=False)
    sort_number: Mapped[int] = mapped_column(Integer, nullable=False)
    child_count: Mapped[int] = mapped_column(Integer, nullable=False, default=0, server_default="0")
    is_hidden: Mapped[bool] = mapped_column(          # ← 상태 플래그
        Boolean, nullable=False, default=False, server_default=false()
    )

    is_deleted: Mapped[bool] = mapped_column(
        Boolean, nullable=False, default=False, server_default=false()
    )
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, default=utcnow
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, default=utcnow, onupdate=utcnow
    )

    def to_domain(self) -> Qux: ...
    @classmethod
    def from_domain(cls, domain: Qux) -> Self: ...

    def hide(self) -> None:
        self.is_hidden = True
        self.updated_at = utcnow()

    def show(self) -> None:
        self.is_hidden = False
        self.updated_at = utcnow()

    # soft_delete() 는 필요 시에만 (Comment 는 미제공)
```

**특징**:
- 상태 전이는 **동사 메서드** 로 (`hide()`, `show()`, `activate()`, `archive()` 등), 제자리 변경
- soft-delete 와 hide/show 는 **독립 개념**. 도메인이 hide/show 만 쓰면 `soft_delete()` 는 미구현 (Comment 예)
- 소프트 삭제 필드는 여전히 보유 (공통 규약). 미사용 시 항상 `False`/`None`
- 구성 파일: `qux_entity.py` 1개

## 패턴 선택 가이드

| 도메인 특성 | Pattern |
|---|---|
| 단일 테이블, 자식 컬렉션 없음 | **Foo** |
| 통계 분리 테이블 (본 도메인의 집계) | **Bar** — audit 미적용 |
| 1:N 자식(enum 리스트 / 복합 VO 컬렉션) 보유 | **Baz** |
| hide/show 등 추가 상태 전이 필요 | **Qux** |

대부분 도메인은 Foo. Baz 는 복합 aggregate(Setup/Series 류). Bar 는 Stats 전용. Qux 는 Comment 류 몇 개뿐.

## 공통 금지 사항

- `Base` 에 컬럼 추가 금지 — 4필드는 각 Entity 가 직접 선언 (C-3, C-4)
- `composite()` / `embedded/` / `collection/` 금지 — 평면 배치
- cross-aggregate `relationship` 금지 — JOIN 은 어댑터의 `select().join()`
- `lazy="select"` / `"dynamic"` / `"joined"` 금지 — `"selectin"` 만
- `Enum(native_enum=True)` (기본값) 금지 — 항상 `native_enum=False`
- naive `datetime` 금지 — `DateTime(timezone=True)` + `utcnow`
- `soft_delete()` 가 새 인스턴스 반환 금지 — 제자리 변경
- Entity 에 비즈니스 로직 금지 — 변환과 전이만
- `entities.py` 등록 누락 금지 — 등록 안 하면 Alembic autogenerate 가 테이블을 못 본다
