# Schema References

add-entity-specs 스킬이 Alembic migration 생성 시 참고하는 레퍼런스.

> **이 문서의 성격 (공통)**
>
> - 기존 서비스 패턴에서 도출된 **참고용** 자료다. 절대 규칙이 아니라 결과물의 경향을 맞추기 위한 가이드.
> - 요구사항이 이 패턴들로 해결되지 않으면, 주변 컨텍스트(폴더/파일/연관 패키지)를 **한 번 더 탐색·검토** 후 필요한 변형을 적용한다.
> - 여러 레퍼런스로 해결 가능하면 **가장 간단한 방식**을 택한다.

## 파일 구조

DDL 은 Alembic migration 으로 관리한다. DB 는 Postgres 한 벌.

```
packages/schema/
├── alembic.ini
└── alembic/
    ├── env.py                 ← be-init 소유. FK 제약 제외 필터 포함
    └── versions/
        ├── 20260926_a1b2c3_article.py       ← 도메인당 1개
        └── 20260926_d4e5f6_comment.py
```

테이블을 추가/변경할 때 **Entity 를 먼저 고치고 autogenerate 로 migration 을 뽑은 뒤 검토**한다. migration 을 손으로 먼저 쓰지 않는다.

## 생성 절차

```bash
# 1. Entity 작성 + entities.py 등록 (entity-references.md)
# 2. Docker Postgres 기동 + 기존 migration 적용
docker compose up -d db
uv run alembic -c packages/schema/alembic.ini upgrade head
# 3. autogenerate
uv run alembic -c packages/schema/alembic.ini revision --autogenerate -m "{domain}"
# 4. 생성된 versions/*.py 검토 (아래 체크리스트)
# 5. 적용 확인
uv run alembic -c packages/schema/alembic.ini upgrade head
uv run alembic -c packages/schema/alembic.ini check   # Entity 와 DB 가 일치하면 "No new upgrade operations detected"
```

Docker 가 없으면 3번 대신 `--sql` 오프라인 모드로 DDL 미리보기만 가능하다. 이 경우 migration 파일은 손으로 쓰되 아래 컬럼 규칙을 그대로 따른다.

## autogenerate 검토 체크리스트

autogenerate 결과를 그대로 커밋하지 않는다. 다음을 확인·수정:

- [ ] `id` 컬럼이 `sa.Identity(always=False)` 인지 — 없으면 Entity 에 `Identity()` 누락
- [ ] `op.create_foreign_key(...)` 가 **없는지** — `env.py` 필터가 걸러야 한다. 있으면 삭제하고 필터를 의심
- [ ] enum 컬럼이 `sa.Enum(..., native_enum=False)` 또는 `sa.String(255)` 인지 — `CREATE TYPE ... AS ENUM` 이 있으면 Entity 의 `native_enum=False` 누락
- [ ] `created_at` / `updated_at` 이 `sa.DateTime(timezone=True), nullable=False` 인지
- [ ] `is_deleted` 에 `server_default=sa.false()` 가 있는지
- [ ] 카운터 컬럼에 `server_default='0'` 이 있는지
- [ ] Stats 테이블과 자식 컬렉션 테이블에 audit 4컬럼이 **없는지**
- [ ] 자식 컬렉션 테이블 FK 컬럼(`{parent}_id`)에 인덱스가 있는지 — 없으면 `op.create_index` 추가 (FK 제약이 없으므로 인덱스도 자동 생성되지 않는다)
- [ ] `downgrade()` 가 `upgrade()` 의 역순인지
- [ ] 다른 도메인의 테이블 변경이 섞여 들어오지 않았는지 — 섞였으면 그 도메인의 Entity 가 DB 와 어긋난 것. 별도 migration 으로 분리

## 공통 컬럼

모든 테이블에 아래 4개 컬럼을 포함한다. **사용 방식**(`soft_delete()` 메서드 추가 / `is_deleted.is_(False)` 필터 사용)만 도메인별로 결정.

Entity 선언 → autogenerate 결과:

```python
sa.Column("is_deleted", sa.Boolean(), server_default=sa.false(), nullable=False),
sa.Column("deleted_at", sa.DateTime(timezone=True), nullable=True),
sa.Column("created_at", sa.DateTime(timezone=True), nullable=False),
sa.Column("updated_at", sa.DateTime(timezone=True), nullable=False),
```

- `created_at`, `updated_at`: Entity 의 `default=utcnow` / `onupdate=utcnow` 가 채운다. DB `DEFAULT now()` 는 두지 않는다 (시각 소스를 애플리케이션 하나로)
- `is_deleted`, `deleted_at`: 모든 테이블이 보유. 도메인별 사용 방식:
  - **정석 soft-delete** (Setup/Series 류): `delete_by_id` 에서 `soft_delete()` 호출, 조회 시 `is_deleted.is_(False)` 필터.
  - **hide/show** (Comment 류): soft-delete 필드는 두되 별도 플래그(`is_hidden`)로 상태 관리.
  - **upsert only** (Rating 류): 삭제 자체를 지원하지 않음.
- `deleted_at` 은 삭제 시점 기록용. 삭제 전에는 NULL.

### 예외 1: Stats 분리 테이블 (Pattern Bar)

분리된 통계 테이블(`*_stats`)은 audit/soft-delete 4 컬럼을 **포함하지 않는다**:

- `id` (PK) + `{domain}_id` (UNIQUE) + 집계 컬럼들만 보유.
- 이유: 통계는 본 도메인과 생애주기 동일, 독자 audit 의미 없음. 쓰기 경쟁이 잦아 최소 컬럼 유지가 락 경합 최소화에 유리.

```python
op.create_table(
    "setup_stats",
    sa.Column("id", sa.BigInteger(), sa.Identity(always=False), nullable=False),
    sa.Column("setup_id", sa.BigInteger(), nullable=False),
    sa.Column("view_count", sa.BigInteger(), server_default="0", nullable=False),
    sa.Column("rating_sum", sa.BigInteger(), server_default="0", nullable=False),
    sa.Column("rating_count", sa.Integer(), server_default="0", nullable=False),
    sa.Column("comment_count", sa.Integer(), server_default="0", nullable=False),
    sa.PrimaryKeyConstraint("id"),
    sa.UniqueConstraint("setup_id"),
)
```

### 예외 2: 자식 컬렉션 테이블 (Pattern Baz 의 자식)

- `id` (PK) + `{parent}_id` + 값 컬럼만. audit/soft-delete **미포함** (부모와 생애주기 동일)
- `{parent}_id` 에 **인덱스 필수** (`ix_{table}_{parent}_id`). FK 제약이 없어 자동 생성되지 않으므로 autogenerate 결과에 없으면 추가

```python
op.create_table(
    "setup_categories",
    sa.Column("id", sa.BigInteger(), sa.Identity(always=False), nullable=False),
    sa.Column("setup_id", sa.BigInteger(), nullable=False),
    sa.Column("category", sa.String(length=255), nullable=False),
    sa.PrimaryKeyConstraint("id"),
)
op.create_index("ix_setup_categories_setup_id", "setup_categories", ["setup_id"])
```

## 타입 매핑

| Python (모델) | SQLAlchemy (Entity) | Postgres |
|---|---|---|
| `str` | `String(255)` / `Text` | `VARCHAR(255)` / `TEXT` |
| `int` (PK) | `BigInteger, Identity(), primary_key=True` | `BIGINT GENERATED BY DEFAULT AS IDENTITY`. `autoincrement=True` 만으로는 SERIAL (실행으로 확인) |
| `int` (FK, 큰 카운터) | `BigInteger` | `BIGINT` |
| `int` (작은 카운터, 순번) | `Integer` | `INTEGER` |
| `bool` | `Boolean` | `BOOLEAN` |
| `datetime` (tz-aware) | `DateTime(timezone=True)` | `TIMESTAMPTZ` |
| `StrEnum` | `Enum(X, native_enum=False, length=255)` | `VARCHAR(255)` |
| `float` | `Float` | `DOUBLE PRECISION` |

## 네이밍 규칙

- 테이블명: **소문자 + 복수형** (예: `users`, `community_posts`)
- 컬럼명: **snake_case** (예: `user_id`, `created_at`)
- 인덱스: `ix_{table}_{column}` (SQLAlchemy 기본 규약)
- migration 파일: `{YYYYMMDD}_{rev}_{domain}` (`alembic.ini` 의 `file_template`)
- migration 메시지(`-m`): 도메인명 소문자 (`article`), 변경이면 `article_add_summary` 처럼 도메인명 접두

## 제약조건 규칙

- **DB FK 제약조건 미사용** — 참조 무결성은 애플리케이션 레벨에서 관리. Entity 의 `ForeignKey(...)` 는 ORM 조인 조건이며 `env.py` 의 `include_object` 가 migration 에서 걸러낸다
- optional 필드 → `nullable=True`
- required 필드 → `nullable=False`
- 카운터 필드 → `nullable=False, server_default="0"`
- UNIQUE 는 도메인 규칙이 명확할 때만 (Stats 의 `{domain}_id`, 유저 email 등)

## migration 파일 예시

**신규 도메인 (`20260926_a1b2c3_example.py`)**:
```python
"""example

Revision ID: a1b2c3
Revises: 
Create Date: 2026-09-26
"""
import sqlalchemy as sa
from alembic import op

revision = "a1b2c3"
down_revision = None
branch_labels = None
depends_on = None


def upgrade() -> None:
    op.create_table(
        "examples",
        sa.Column("id", sa.BigInteger(), sa.Identity(always=False), nullable=False),
        sa.Column("name", sa.String(length=255), nullable=False),
        sa.Column("is_deleted", sa.Boolean(), server_default=sa.false(), nullable=False),
        sa.Column("deleted_at", sa.DateTime(timezone=True), nullable=True),
        sa.Column("created_at", sa.DateTime(timezone=True), nullable=False),
        sa.Column("updated_at", sa.DateTime(timezone=True), nullable=False),
        sa.PrimaryKeyConstraint("id"),
    )


def downgrade() -> None:
    op.drop_table("examples")
```

**기존 도메인에 컬럼 추가 (`20260927_b2c3d4_example_add_summary.py`)**:
```python
def upgrade() -> None:
    op.add_column("examples", sa.Column("summary", sa.String(length=255), nullable=True))


def downgrade() -> None:
    op.drop_column("examples", "summary")
```

NOT NULL 컬럼을 기존 테이블에 추가할 때는 `server_default` 를 함께 주거나, nullable 로 추가 → 백필 → NOT NULL 변경의 3단계로 나눈다.
